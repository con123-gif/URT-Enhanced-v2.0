## Method and correctness
Disk CSR stores little-endian uint64 offsets and uint32 dense neighbor IDs (8(V+1)+4E bytes per orientation). Original tagged IDs must have a separate immutable bijective sidecar, with digests bound to the authenticated export receipt; test adapter maps numeric fixture IDs, does not equate display names. Reader checks exact file sizes, supplied SHA256, monotonic offsets, end count and neighbor ranges. Assumes immutable files through validation/query (no adversarial file replacement or mutation); not receipt authentication. Native positional read via os.pread and a 64-page 4096-byte LRU, 262144-byte retained raw graph block limit plus one transient page, Python objects and digest read buffers. Validation scans all graph bytes, O(V+E); subsequent sparse queries need not inspect unreachable vertices. Reverse reader requires a verified transpose; test writer creates it from the identical rows, not a production external sort. Raw export and typed edge-role evidence remain mandatory.

A mask records bits already received by each reached node; pending records only newly received, not-yet-propagated bits. Each bit enters a node at most once, every propagation is along an actual edge, and queue exhaustion means every reached node's bits have crossed its outgoing edges. Induction on path length proves equality with separate reachability for every worker, including cycles. For K<=32, O(S+K*(Vr+Er)) expected dictionary operations, hence linear in reached graph for fixed K. Unlike run4 SCC traversal, an edge may be read repeatedly when distinct bits arrive separately (up to K times). Active state O(Vr), raw block cache fixed; peak process memory not fixed independently of reachable output. This is a sparse reader/propagator complement to run4 dense SCC, not arbitrary proof search. A production bounded-RAM full CSR construction/transpose and authenticated tagged ID sidecar remain open.
